# Office UI architecture

The frontend is plain HTML, CSS, and JavaScript in `apps/office-ui/`, served by FastAPI. There is no frontend package installation or build step.

- `GET /` serves `index.html`.
- `/assets/*` serves JavaScript and styles.
- `OFFICE_UI_PATH` selects the directory (default `./apps/office-ui`; Docker `/ui`).
- Hash routes select feature views, with `#floor` as the default.

See the [user guide](../OFFICE_UI.md) for the office tour.

## Views

| Route | Surface |
| --- | --- |
| `#floor` | Spatial office, agent inspectors, team/project grouping, room shortcuts, and activity feed |
| `#people` | Human/agent directory, search/type filter, and human entry creation/removal |
| `#team` | Agent roster, creation entry point, chat, configuration, and removal |
| `#chat` | Unified Office/agent channel, history, streaming responses, and inline approvals |
| `#memory` | Personal working notes and shared OKF facts |
| `#approvals` | Approval proposal and decision board |
| `#analytics` | Active/recent runs and run inspection |
| `#stacks` | Inference connections and coding runtimes |
| `#local-models` | Ollama catalog, pull, unload, removal, and health checks |
| `#connect` | API entry point and explicit planned external connectors |
| `#office-config` | Orchestrator model, memory, and default operating limits |

## Live floor data

`refreshOffice()` reads `/agents`, `/office/activity`, pending `/approvals`, and `/office/people` together. It polls every three seconds when the document is visible, with a ten-second timeout per request. Failed updates retain the last snapshot and display a stale-data warning. Unchanged floor snapshots retain the desk DOM; changed snapshots restore focus to the selected desk or room where possible.

`office-scene.js` renders the 3D voxel scene with a locally vendored Three.js 0.180.0 module pair. `voxel.css` supplies the scene overlay and dark workspace theme. No CDN request or frontend build is needed. See the [vendor manifest](../../apps/office-ui/vendor/README.md) for provenance and reproduction commands.

The app publishes an `office-snapshot` event and keeps the latest snapshot for module initialization. `office-layout.mjs` plans at most four rows per virtual floor and supports search, team/project grouping, and clamped pagination for mixed human/agent rosters. The scene groups the filtered roster into desk islands and rebuilds only when relevant data changes. Camera state survives polling. Shared box geometry and cached materials reduce allocation; shadows refresh on scene rebuild. Active typing renders at a capped rate and pauses when hidden or reduced motion is enabled. Labels are real DOM buttons projected onto the scene, so feature navigation remains keyboard accessible.

The HTML/SVG floor remains as a fallback when WebGL initialization fails or the context is lost. Animations follow active-run status, and `prefers-reduced-motion` disables them. Team/project grouping derives from agent definitions; it does not infer communication or delegation.

## Presence and journal

`GET /office/activity` returns `active` and `recent` lists scoped to `get_user_id`. The community UI sends `X-User-Id: admin`; this convention is not an authentication boundary.

`ChatRunService.stream_agent_chat()` wraps the adapter stream and records presence in an `ActivityStore` SQLite database alongside the journal. A heartbeat runs every ten seconds; entries expire after 35 seconds. Completion, exceptions, and stream closure cancel the heartbeat and remove the presence row. Workers sharing this database see the same presence.

Presence records contain run metadata and stage/tool indicators, not prompt text, response tokens, or thinking text. Recent journal entries are user-scoped, newest first, limited to 100, and exclude approval audit records. The run inspector requests recorded thinking separately from `/runs/{run_id}/thinking`.

## Human directory and memory UI

`GET/POST /office/people` and `DELETE /office/people/{id}` store human directory records in the existing SQLite database. The read response annotates the current request identity and includes it as an unsaved operator entry if needed. Entries have ID, name, team, and job title. They are not authentication accounts, permission roles, invitations, or live presence. The current community identity mechanism remains unchanged.

The memory UI uses existing gold/OKF endpoints. It presents structured notebook entries separately from shared fact cards and excludes `g_system` from working-note counts. Shared fact creation exposes the existing type, projects, tags, sensitivity, and pinned fields. Search and filters operate on the loaded team's facts, rendering 24 matches at a time. The people directory renders 36 matches at a time.

## Verification

Run JavaScript syntax and backend tests from the repository root with the development environment activated:

```bash
node --check apps/office-ui/app.js
node --check apps/office-ui/office-scene.js
node --test apps/office-ui/tests/*.test.mjs
python -m pytest apps/orchestrator/tests
```

For visual changes, check desktop and mobile layouts, both seating arrangements, desk dialogs, room navigation, camera rotation/zoom/reset, expanded view and Escape, empty states, disconnected updates, WebGL fallback, and reduced motion. Do not seed fake agents or live activity into the user's office for screenshots.
